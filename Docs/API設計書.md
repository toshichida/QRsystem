# API 設計書

## 1. 文書の目的

本書は、QR コード受付システムで利用する **HTTP API・GAS 契約・Google 組み込み API** の入出力と責務を定義する。実装時の関数名は GAS／フロントのコードと一致させるが、本書では **契約（プロトコル）** を優先して記載する。根拠は [要件定義書](./要件定義書.md) および [アーキテクチャ設計書](./アーキテクチャ設計書.md) とする。

## 2. API の区分

| 区分 | 呼び出し元 | 概要 |
|------|------------|------|
| GoQR（外部 HTTP） | GAS のみ | QR 画像バイナリの取得 |
| GAS Web アプリ | GitHub Pages 上のフロント | 受付記録・マスタ照会 |
| Google 組み込み API | GAS のみ | スプレッドシート・Gmail |

**ブラウザから Google Spreadsheet／Gmail を直接呼ばない。**

---

## 3. GoQR API（QR 画像生成）

### 3.1 概要

- **用途**: 参加者 ID 文字列を QR 画像（PNG 等）として取得し、メールに添付する。
- **公式情報**: [GoQR.me API](https://goqr.me/api/)（エンドポイント・パラメータは同ドキュメントに準拠する）。

### 3.2 想定リクエスト（例）

実装では `UrlFetchApp.fetch` 等で **GET** する。

| 項目 | 内容 |
|------|------|
| メソッド | `GET` |
| ベース URL | ドキュメント記載の生成 URL（例: `https://api.qrserver.com/v1/create-qr-code/` 系） |
| 主なクエリ | `data`（必須: 参加者 ID 文字列）、`size`（例: ピクセル）、`format` 等 |

### 3.3 レスポンス

| 項目 | 内容 |
|------|------|
| ボディ | 画像バイナリ（PNG 等） |
| 利用 | GAS で Blob 化し、`GmailApp` / `MailApp` の添付に渡す |

### 3.4 エラー

- HTTP 4xx/5xx 時は GAS 側でログ出力し、該当参加者のメール生成を失敗扱いにする方針とする（詳細は実装で定義）。

---

## 4. GAS Web アプリ（受付 API）

フロントは **同一オリジンではない**（GitHub Pages と `script.google.com` ドメイン）ため、GAS 側で **CORS** を返す。エントリは `doPost` を主とする（`doGet` はヘルスチェック用に任意）。

### 4.1 エンドポイント

| 項目 | 内容 |
|------|------|
| URL | GAS の「ウェブアプリ」デプロイ後に発行される URL（`/exec`） |
| メソッド | `POST` |
| `Content-Type` | `application/json` |

### 4.2 リクエストボディ（JSON）

| フィールド | 型 | 必須 | 説明 |
|------------|-----|------|------|
| `action` | string | 任意 | 将来拡張用。初期は `"checkIn"` 固定でも可 |
| `participantId` | string | 必須 | QR から読み取った参加者 ID |
| `staffMemo` | string | 任意 | スタッフメモ |
| `passphrase` | string | 必須 | 簡易認証用の合言葉（[要件定義書 §7.3](./要件定義書.md)） |

### 4.3 レスポンス（成功時）

HTTP `200`。ボディは JSON 例:

| フィールド | 型 | 説明 |
|------------|-----|------|
| `ok` | boolean | `true` |
| `participant` | object | マスタから取得した表示用フィールド（氏名・部署等）。設定で指定する列に対応 |
| `log` | object | 追記したログの要約（受付日時等） |

表示するキーは **設定シートまたは `AppConfig`** と整合させる（実装で確定）。

### 4.4 エラー時

| HTTP | 条件 | ボディ例 |
|------|------|----------|
| `401` | 合言葉不一致 | `{ "ok": false, "error": "unauthorized" }` |
| `404` | マスタに `participantId` なし | `{ "ok": false, "error": "not_found" }` |
| `400` | JSON 不正・必須欠落 | `{ "ok": false, "error": "bad_request" }` |
| `500` | サーバ／シート書込み失敗 | `{ "ok": false, "error": "internal" }` |

実装で **200 + `ok: false`** に統一する場合は、本表と [実装計画書](./実装計画書.md) を合わせて更新する。

### 4.5 CORS

| ヘッダ | 値 |
|--------|-----|
| `Access-Control-Allow-Origin` | GitHub Pages のオリジン（例: `https://<user>.github.io`）。ワイルドカードは本番では避ける |
| `Access-Control-Allow-Methods` | `POST, OPTIONS` |
| `Access-Control-Allow-Headers` | `Content-Type` |

プリフライト `OPTIONS` に対し、上記を返す。

### 4.6 備考

- GAS ウェブアプリの **実行ユーザー**（アクセス権限）は「自分」または「組織」等、スプレッドシート編集に必要な権限でデプロイする（[要件定義書 §8.2](./要件定義書.md)）。

## 5. Google 組み込み API（GAS 内のみ）

ブラウザからは呼ばず、GAS スクリプト内でのみ使用する。

### 5.1 SpreadsheetApp / スプレッドシート操作

| 用途 | 概要 |
|------|------|
| 初期化 | シート作成・ヘッダー行・列幅等（[要件定義書 §4.1](./要件定義書.md)） |
| マスタ参照 | `participantId` で行検索 |
| ログ追記 | `ReceptionLog` 相当シートに行追加（再スキャンは別行） |

### 5.2 GmailApp / MailApp（下書き・送信）

| 用途 | 概要 |
|------|------|
| 下書き作成 | 宛先ごとに 1 通、QR 添付・本文（[要件定義書 §5](./要件定義書.md)） |
| 一斉送信 | 下書きフォルダ内の対象を送信（ルールは実装で固定） |

---

## 6. フロントが利用しない API

- **Gmail API（REST）** を OAuth でフロントから直接呼ぶ方式は採用しない。
- **Sheets API v4** をフロントから直接呼ぶ方式は採用しない。
