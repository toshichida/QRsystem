# リポジトリ構造定義書

## 1. 文書の目的

本書は、QR コード受付システムのリポジトリにおける **ディレクトリ階層と役割** を定義する。実装時の配置の単一の参照先とし、[要件定義書](./要件定義書.md) の前提（GAS・GitHub Pages・`gh` デプロイ）と整合させる。

## 2. 対象読者

- 本リポジトリで実装・デプロイを行う開発者・運用者
- コードレビューやオンボーディングを行う者

## 3. 推奨リポジトリ構成（ASCII ツリー）

実装フェーズでは、以下を原則としてディレクトリを揃える。差分が生じた場合は本書を更新する。

```text
QRsystem/
├── Docs/
│   ├── 要件定義書.md
│   ├── リポジトリ構造定義書.md
│   ├── アーキテクチャ設計書.md
│   ├── API設計書.md
│   └── 実装計画書.md
├── gas/
│   ├── appsscript.json          # GAS マニフェスト（clasp 利用時）
│   ├── .clasp.json              # clasp: scriptId / rootDir（ローカル開発時、gitignore 検討）
│   └── src/                     # .gs または TypeScript（ビルド方針に依存）
│       ├── Code.gs              # エントリ・Web アプリ doGet/doPost 等（仮称、実装で確定）
│       ├── SetupSpreadsheet.gs
│       ├── MailQr.gs
│       └── ReceptionApi.gs
├── web/
│   ├── index.html
│   ├── css/
│   ├── js/
│   └── assets/                  # 任意: 静的アセット
├── .github/
│   └── workflows/               # 任意: CI / Pages 用（運用で追加）
├── .gitignore
└── README.md
```

### 3.1 ツリーに含めない／任意のもの

| パス | 説明 |
|------|------|
| `node_modules/` | フロントでビルドツールを使う場合のみ生成。本書のツリーには含めない。 |
| `dist/` または `web/dist/` | ビルド成果物を別ディレクトリに出す場合。Pages の公開ルートと合わせて README に記載。 |

## 4. ディレクトリ・ファイルの役割

| パス | 役割 |
|------|------|
| `Docs/` | 要件・設計・実装計画など、プロジェクト文書を集約する。 |
| `gas/` | Google Apps Script のソース。スプレッドシート初期化、メール・GoQR、Web アプリ API を配置。clasp で push/pull する想定。 |
| `web/` | GitHub Pages で公開する受付フロント（HTML5・QR 読取 UI）。静的ファイルのルートとする。 |
| `.github/workflows/` | `gh` や Actions によるデプロイ自動化を行う場合にワークフローを置く（任意）。 |
| `README.md` | セットアップ、スプレッドシートと GAS の紐づけ、`gh` による Pages デプロイの要点へのリンク。 |

## 5. GitHub Pages と `web/` の対応

- **公開コンテンツのソース**は `web/` を正とする（`index.html` をルートに置く構成）。
- **GitHub Pages** の公開ルートは、リポジトリ設定で **`/ (root)`** に `web/` の内容を載せるか、**`docs/` フォルダ**を公開ルートにするか、**Actions で `web/` を `gh-pages` ブランチへ出力**するかのいずれかを選ぶ。いずれの場合も **ビルド後にブラウザが読み込むファイルが `web/` で開発した成果と一致**することを要件とする。
- **デプロイ操作**は [要件定義書 §2.3・§7.4](./要件定義書.md) に従い、**GitHub CLI（`gh`）** から実行可能な手順とする。具体的な `gh` サブコマンドやブランチ戦略は [実装計画書](./実装計画書.md) または `README.md` の運用節で定義する。
